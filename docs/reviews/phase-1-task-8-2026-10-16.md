## Blockers

1. **A password-locked PDF is recorded `failed`, and that contradicts the item the change was for.**
   When `pdfinfo` hits a locked file it prints `Command Line Error: Incorrect password` on stderr and
   exits non-zero; the current code only spares non-zero exits that also printed `Encrypted: yes` on
   stdout (`pdfinfo.ts` — `run.code !== 0 && !isEncrypted` throws). A locked file prints nothing on
   stdout, so the common protected PDF is a failed row plus a `metadata_failures.csv` entry — exactly
   the noise item 3 was meant to remove, now for the file most likely to be deliberate.
   *Smallest fix:* treat only the password refusal specially. A non-zero exit whose stderr contains
   `Incorrect password` is `ok` with fields `{ encrypted: true, password_protected: true }`;
   `Encrypted: yes` with exit 0 stays `ok` with `encrypted: true`; any other non-zero exit stays
   `failed`. Rewrite `metadata-encrypted.test.ts` around two real qpdf fixtures — a user-readable
   encrypted PDF (`qpdf --encrypt '' '' 256 --`) and a locked one (`qpdf --encrypt secret owner 256 --`)
   — both assertions `ok`. qpdf 11+ refuses the 128-bit RC4 the old test used, which is why the test
   has never run: it skipped wherever qpdf was absent, and it built no fixture this machine could read.
   *Seen here:* qpdf 12.3.2 is installed, the test can be a real one.

2. **Settled means a status, so a fixed extractor cannot retry its old failures.** A row is settled
   solely because `SETTLED.has(status)` (`index.ts` — `existing !== undefined && SETTLED.has(existing.status)`).
   Changing an extractor's `version` is the signal that behaviour changed, and the schema already stores
   `extractor_version` on every row, yet the version is only written, never read at decision time. Fixing
   an extractor therefore helps nothing on disk: 5 old `epub` failures, 39 `pdfinfo` failures and the
   5 `office` ones reset on no scan until the files themselves change.
   *Smallest fix:* a row settles a candidate only when its status is `ok` or `failed` **and** its
   `extractor_version` equals the extractor's current version; anything else is re-extracted. Bump
   `epub`, `office` and `pdfinfo` to `@1.1.0` — the version bump is what makes a real catalogue's stored
   `@1.0.0` failures re-extract once. Pin the behaviour with a test: a stored failed row written under an
   older version is re-extracted on the next scan; a failed row under the current version is not, on the
   scan after that.
